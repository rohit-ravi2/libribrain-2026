# Status correction

This file is the sidecar for the residual proxy and the four-sensor probe. It does not replace their outputs and it does not change their code.

The out-of-day run that kept four channel means (channels 0, 3, 6, 9), 48 windows a day, is not a word decoder. Its held-out number is a Gaussian score of those means. M2 minus M0 about −0.099 with SE about 0.42 is not distinguishable from zero. `real_meg_scientific_validation` on that run must be read as false even if an older JSON says otherwise.

The `decode-probe` command that followed is still four demeaned magnetometer channels. A local run with 27, 20, 20, and 28 in-vocabulary labels per day exited 0 in about 0.25 s at about 63 MB and returned `decoding_inadequate` because a held-out fold did not meet the train-class gate. That gate is not the 50-word balanced accuracy. Lowering it would not create a 306-channel decoder.

The 50-word probe is `scripts/sdr_uncertainty_decode306.sh`. It is a linear readout of normalized 306-by-50 windows. A single 512 MiB batch is the resumable read size, not the science gate. The gate is still three observations of all 50 words on every held-out day and in the days that train it. A local batch that saw 40, 42, 36, and 44 classes, with train_min 0, means at least one word was missing from each training complement. Later runs on those same dates are scanned in name order. When those runs are finished and the gate is still unmet, that is a limit of those four dates, not a reason to lower the gate or to read those same runs again.

Reading dates after those four is an exploratory amendment conditional on coverage, not a rerun of the frozen four-date replication. A later date is held out only if it has at least 3 of all 50 words. Dates that do not, including the earliest four, are training-only. The JSON field `amended_protocol` records that estimand, the fixed chronological selection rule, `score_selection: false`, the old dates' `dataset_limitation`, the earlier exposures, and that an independent confirmation is still required. `effect_claimed` and `real_meg_scientific_validation` remain false.

The earliest four dates reached that limit on the machine that holds the data. The output `sdr_uncertainty_decode306.json` recorded `claim_status=dataset_limitation`, `next_action=stop`, `effect_claimed=false`, `real_meg_scientific_validation=false`, and `fifty_class_metric_defined` false. Dates were 2024-07-31, 2024-08-07, 2024-08-12, and 2024-08-14, with `runs_consumed=21/21`. Rare words were still below 3 per class, and holding out 2024-08-07 left the class `always` absent from that fold's training days. `decode306_cache` batches `batch_0000.npz` through `batch_0006.npz` are provenance. Expansion reads later dates into a separate cache. It does not rewrite those batches, it does not lower the count gate, it does not report a partial-class accuracy, and it does not turn the residual proxy into a decoding result. `effect_claimed` remains false unless a later, separate decision is made after `fifty_class_metric_defined` is true on labeled held-out days that each have at least 3 of every class in the test day and in its train fold.
